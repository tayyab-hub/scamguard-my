# Final screenshot capture checklist
Use only authentic captures from the reviewed release or an explicitly labelled local test environment.
No generated mockup can stand in for a functioning screen. Historical docs/screenshots remain historical.
Task 9 automated PNGs under frontend/test-results are local controlled test evidence, not production data.

Before capture: record date, commit, browser/version, viewport, environment and fixture; turn off
notifications; use a controlled account; remove personal history, password fields, reset tokens,
database URLs, provider environment pages and developer storage/token views. Check the final image,
not just the browser. Do not upload sensitive screenshots to an external service.

| Capture | Exact screen/action | Caption/evidence purpose |
| --- | --- | --- |
| Login | /login with empty password | Accessible account entry |
| Dashboard | Local controlled account with genuine saved records | Measured owned distributions; label environment |
| Message input | Analyse → Message; fixtures.json scam_like | Explicit input/consent |
| Message result | Submit once; show result hero + evidence/actions | ELEVATED for current fixture; advisory outcome |
| URL result | Analyse conventional or brand_structure fixture | Local structure and no-fetch boundary |
| Phone result | Fixed-line fixture | Insufficient Evidence, metadata not identity |
| QR upload | Select data/demo/task9/url.png before Analyse | Bounded upload and explicit action |
| Camera scanner | Real user-started physical scan, prior to detection | State exact device/browser; do not use synthetic frame as hardware proof |
| QR result | Stopped preview and saved routed result | No auto-open; original image not retained |
| History filters | Search/type/risk/sort with known local records | Find and reopen immutable result |
| Account | Controlled full name/username, hide private email if necessary | Owned profile; no password/reset tokens |
| Architecture | Render Mermaid from ARCHITECTURE.md | Components/trust boundaries |
| Database | Render Mermaid from DATABASE.md | Ownership/FKs/cascades |
| Testing | Clean final summary with command/version/date | Exact counts and skips; never show connection strings |

Capture desktop at 1440px and mobile at 390px; use 320px only where discussing stress testing.
Scroll to the relevant region; full-page stitches can place fixed navigation across the image.
Inspect text readability, clipping, focus, overflow and unintended personal data.
Record omissions explicitly in the report rather than filling them with fabricated images.

Suggested caption: “Figure N. [Behavior], [local controlled test / production], commit [SHA],
[browser/version], [viewport/device], captured [date]. Fixture [name].”
The live camera caption must say whether physical capture or synthetic automated regression was used.
