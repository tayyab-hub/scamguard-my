# Code comment coverage and verification

Documentation-only inspection completed **28 October 2026**. Start learning with the [beginner walkthrough](SCAMGUARD_CODE_WALKTHROUGH_FOR_BEGINNERS.md).

## Scope and counting method

- **172 human-authored source/configuration files inspected** in the tracked Python, TypeScript/TSX, JavaScript/MJS, CSS, HTML, PowerShell, CMD, YAML and Alembic-template inventory.
- **164 files received explanatory comments**; **8 short package markers already had sufficient namespace descriptions** and remain unchanged.
- The inventory includes application code, migrations, training/evaluation utilities, tests, browser fixtures, launchers, CI/deployment declarations and academic-generation source. “Inspected” means responsibilities, important symbols, branches, fixtures/assertions and callers were reviewed; repetitive static fixtures/UI text were examined selectively. This is not a measured runtime test-coverage percentage or a claim of formal verification.
- The worktree was clean at the initial audit. All original source lines remain in order; changes to those 164 files consist solely of inserted ordinary comments and blank lines. Existing Python docstrings remain byte-for-byte in their source lines and unchanged in the parsed syntax trees.
- Source comments explain purpose and important inputs/outputs, error/edge cases, state/transaction ownership, security boundaries and algorithms. Straightforward test names/assertions are not padded with repetitive explanations.

The preliminary audit also read `CODEX.md`, `PROGRESS.md`, `ROADMAP.md`, `README.md`, `DECISIONS.md`, architecture/data-flow/API/database/security/ML/QR/testing documentation and relevant non-commentable configuration. Research artifacts were consulted as evidence where needed and were not annotated or regenerated.

## Clarifications and limits discovered during inspection

1. **QR routing and optional review:** `QRIntelligenceEngine` shares the configured Message engine. Eligible routed text can reach the optional reviewer when enabled. Added explicit source/package comments and clarified `QR_INTELLIGENCE.md` and `PRIVACY_MODEL.md`; local decoding/on-device frames do not establish an unconditional no-provider claim. No live provider was enabled or called during this pass.
2. **Payment integrity wording:** corrected the older QR guide's “at most CAUTION” and blanket “never adds severity” statements. Current code imposes a caution floor for invalid payment integrity and preserves higher routed risk. The implementation was not changed.
3. **Historical docstrings:** `db/base.py` still contains its Task 1 no-domain-table description and `db/models.py` its Task 3-only description. Current-scope comments now explain all five tables/four input modes immediately above them. The QR package's legacy local/deterministic wording also has a precise routing qualifier. Docstrings were preserved to avoid changing introspection/public documentation.
4. **Unavailable UI fixtures:** Task 1/test milestone wording describes unavailable-capability scenarios, not current absence of all analysis features. Comments distinguish real runtime behavior from explicit mocked responses. Historical release filenames and evidence remain dated records.
5. **Scores and uncertainty:** Message fusion points and URL ordinal category indexes have different meanings. Phone usually abstains; valid metadata is not caller trust. Provider confidence, CRC validity and successful QR decoding are not safety guarantees.
6. **Persistence boundaries:** analysis has several durable commits and no queue/idempotency key. A lost response can follow a successful write; a terminated process can leave unfinished state. History reads stored decisions. Snapshot consistency and ownership depend on the explicit transaction/query code, not frontend visibility.
7. **Production/proxy assumptions:** trusting forwarded client addresses assumes a trusted proxy boundary. Source/settings inspection cannot establish current hosting secrets, runtime configuration, email delivery or production health. The privacy guide now distinguishes dated deployment observations from locally verified source behavior.
8. **Redaction/payment/ML limits:** redaction covers recognized patterns, payment parsing covers a subset of the format, and held-out/controlled tests do not establish universal accuracy. Models and thresholds were not changed to fit examples.
9. **Academic scripts:** report/figure generators contain dated evidence and template assumptions. Their source/helpers are documented but they were not executed, so no newly rendered academic-artifact quality claim is made.
