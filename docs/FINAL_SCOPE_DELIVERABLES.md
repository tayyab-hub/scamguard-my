# Scope and deliverables

SCAMGUARD serves individual users who can enter or upload a suspicious item and read a brief evidence explanation, including students and staff reviewing unfamiliar messages or links, and members of the public examining a number or QR code before responding. A secondary audience is an assessor or educator examining reproducible analysis and privacy controls. These are intended user groups, not a claim that a representative sample has been studied. The current language/data evidence is strongest for English SMS and the selected URL corpus; universal language or geographic coverage is not claimed.

Execution follows Browser → Vercel React frontend → same-origin API proxy → Render FastAPI → Neon PostgreSQL. Local engines run in the backend. Camera frames are decoded on the client; an uploaded image is decoded transiently on the backend. Only explicit analysis submits decoded camera text. The shared application stores private assessments and does not visit submitted destinations or contact telephone subscribers. Figure 1 in [FINAL_FIGURES.md](FINAL_FIGURES.md) shows these boundaries.

Development used incremental tasks, reviewed commits, regression verification and a final feature freeze. Message model candidates were selected using validation macro F1 before a held-out test; URL candidates used domain-separated partitions. Phone metadata and QR/payment parsing are deterministic. Task 9 corrected privacy edge cases and strengthened verification without changing intelligence methodology. The evidenced Git window is 3–12 September 2026; it does not establish the date work originally began. Full chronology and missing academic deadlines are in [PROJECT_PLAN.md](PROJECT_PLAN.md).

Out of scope are public/community reporting, moderation, campaign intelligence, adaptive learning, general OCR, live webpage fetching, live URL/Phone reputation, subscriber identification, payment authorization, complete payment-scheme certification and a cross-modal fraud probability. Optional backend external AI review exists but is disabled by default and in the recorded evaluation. No new infrastructure or major feature is part of this academic pass.
