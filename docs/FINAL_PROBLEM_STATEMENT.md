# Problem statement

An individual deciding how to respond to an unfamiliar message may also need to examine a link, a telephone number or a QR payload associated with it. These objects expose different evidence: message wording can contain a request, a URL can contain misleading structure, and a telephone number can describe a numbering range without identifying its current caller. A QR symbol can conceal any of these objects until it is decoded. The decision problem is therefore how to inspect the available evidence before taking an action, while recognising what the evidence cannot establish.

The related-system review identifies complementary approaches. VirusTotal aggregates file and URL analysis; Google Safe Browsing checks URLs against threat information; and Truecaller provides caller/spam information and a web Scam Checker for telephone numbers and URLs (VirusTotal, n.d.-a, n.d.-b; Google, 2026a, 2026b; Truecaller, n.d.-a, n.d.-b, n.d.-c). These capabilities mean that multi-input checking is not unique to SCAMGUARD. The selected systems do not document the same combination of reproducible local Message and URL models, conservative Phone metadata, consent-based QR decoding, evidence explanations and an owner-controlled assessment history. This is a bounded design comparison, not proof that no other product offers the combination.

SCAMGUARD addresses that integration problem through four explicitly selected analysis modes in one authenticated web application. QR routes supported decoded content to the same analysis engines; it does not introduce a fourth fraud classifier or fuse unrelated inputs into a single probability. The shared result structure presents observed indicators, separate confidence and risk, limitations, and suggested verification actions. Private history preserves the assessment and its method versions so that users can revisit the reasoning.

The intended contribution is an inspectable decision-support workflow. The project does not establish that it prevents financial losses, verifies an identity, or determines whether a payment is legitimate. Publicly documented capabilities motivate the design, while implemented controls and recorded tests establish its technical feasibility. Direct evidence of improved user decisions remains NOT YET EVIDENCED; the planned formative study tests comprehension rather than assuming it.
